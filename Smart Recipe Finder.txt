Smart Recipe Finder — Complete Project Understanding Guide
1. Project Overview
Project Name
Smart Recipe Finder
Project Type
Full-stack web application with AI integration.
Main Goal
The system helps users:
•	Search recipes using ingredients or recipe names
•	Apply filters like vegan, gluten-free, and difficulty level
•	Avoid allergen ingredients
•	View nutrition information
•	Save favorite recipes
•	Create shopping lists
•	Generate AI-based recipe summaries
________________________________________

Spoonacular API	To fetch real-time recipe data
Gemini AI	To generate AI-based recipe summaries
Axios	To send API requests from React frontend
Azure	To deploy application online

6. Authentication Flow (Spring Boot + JWT)
Why Separate Authentication Service?
Authentication was separated to keep security logic modular and maintainable.
Spring Boot handles:
•	Login
•	Registration
•	JWT generation
________________________________________
Complete Login Flow
User enters email/password
          ↓
React sends login request
          ↓
Spring Boot validates credentials
          ↓
JWT token generated
          ↓
Token returned to React
          ↓
React stores token in localStorage
________________________________________
Why JWT?
JWT is used because:
•	It is secure
•	Stateless authentication
•	No server-side session required
•	Easy frontend-backend communication
________________________________________
How JWT Works in Project
After Login
Authorization: Bearer <token>
This token is attached with every protected request.
________________________________________
Backend Validation Flow
Request comes with token
         ↓
.NET middleware validates token
         ↓
If valid → request allowed
If invalid → 401 Unauthorized

9. Database Design — Complete Understanding
USER TABLE
Purpose: Stores user account information.
Important fields:
•	Name
•	Email
•	PasswordHash

•	DietPreference
Why AgeGroup & DietPreference? For personalization.
________________________________________
RECIPE TABLE
Stores recipe metadata.
Important fields:
•	Title
•	Category
•	Difficulty
•	CookingTime
•	IsVegan
•	IsGlutenFree
Why? To support filtering.
________________________________________
INGREDIENT TABLE
Stores ingredient information.
Important field:
•	AllergyFlag
Why? To identify allergen ingredients.
________________________________________
RECIPE_INGREDIENTS TABLE
This is a junction table.
Relationship:
Recipe ↔ Ingredient
Why used? Because:
•	One recipe has many ingredients
•	One ingredient can belong to many recipes
This is many-to-many relationship.
________________________________________
NUTRITION_INFO TABLE
Stores:
•	Calories
•	Protein
•	Carbs
•	Fats
•	Sugar
•	Fiber
Relationship: One recipe → One nutrition record.
Why? To show health information.
________________________________________
FAVORITE TABLE
Relationship:
User ↔ Recipe
Why? To allow users to save favorite recipes.
________________________________________
SHOPPING_LIST TABLE
Purpose: Stores:
•	Ingredient names
•	Quantity
•	Recipe mapping
Why? To support meal planning and grocery management.
________________________________________
AI_SEARCH_HISTORY TABLE
Purpose: Stores:
•	User search query
•	AI-generated summary
•	Search date
Why?
•	Avoid repeated AI calls
•	Improve performance
•	Maintain history

The application allows users to search recipes using ingredients and filters like vegan or gluten-free, supports allergy-aware filtering, nutrition details, favorites, shopping lists, and AI-generated recipe summaries.
Authentication is handled separately using Spring Boot and JWT, while the .NET backend manages business logic, filtering, database operations, and external API integrations like Spoonacular and Gemini AI.”
This is your safest and strongest intro.
